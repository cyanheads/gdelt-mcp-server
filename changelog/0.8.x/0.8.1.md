# 0.8.1 — 2026-11-01

## Added

- **`staleResponse`** on every DOC and TV tool: when the refetch of a request is rate-limited, fails, or comes back empty, the server returns GDELT's stored answer from that request and reports `fetchedAt`, `ageSeconds`, and `reason` (`gdelt_rate_limited`, `gdelt_unavailable`, `gdelt_empty`). Answers are kept 24 hours; the stored answer holds nothing published after `fetchedAt`. ([#74](https://github.com/cyanheads/gdelt-mcp-server/issues/74))
- **Local GKG mirror** the four DOC tools (`gdelt_search_articles`, `gdelt_get_coverage_timeline`, `gdelt_get_tone_distribution`, `gdelt_get_coverage_breakdown`) answer from when the DOC API refuses a request or returns nothing, marked by `source`, `attempts`, and `coverage`. Off unless `GDELT_MIRROR_PATH` is set; `GDELT_MIRROR_WINDOW_DAYS` sets the days kept (default 7, 1–90). Build it with `bun run mirror:init`, `mirror:refresh`, and `mirror:verify` from a checkout or the Docker image, which carries the scripts and a `/var/lib/gdelt-mirror` mount point; the npm package does not ship them. DOC is held to a 45 s fallback budget when the mirror stands behind it, the mirror answers by 55 s, and a query over 1,000 characters is not answered from it. ([#75](https://github.com/cyanheads/gdelt-mcp-server/issues/75))
  - Mirror keywords match article titles and entity names, and counts, shares, and the `volume_raw` denominator come from mirrored articles, so figures differ from DOC's; the answer's notice says so.

## Changed

- **DOC empty-result notices** add a sentence to retry the same call later, since GDELT also answers empty under load. Mirror answers do not carry it. ([#77](https://github.com/cyanheads/gdelt-mcp-server/issues/77))
- **Date-field descriptions** on `gdelt_get_coverage_timeline`, `gdelt_get_coverage_breakdown`, and `gdelt_get_tone_distribution`, and the server instructions, state which modes accept an explicit window older than 3 months (timeline `volume` and `tone`, both breakdowns, tone distribution) where they said the window covers the last 3 months. Validation is unchanged. ([#16](https://github.com/cyanheads/gdelt-mcp-server/issues/16))

## Fixed

- **Relative windows** resolve in UTC, as GDELT reads `timespan`: on a daylight-saving transition day in the server's time zone `1d`/`24h` spanned 25 h or 23 h, and a TV station whose end date is today read as inactive east of UTC. The `timespan` string still goes to GDELT unchanged; the resolved window feeds notices, continuation windows, stale-serve age limits, and the mirror's window. ([#78](https://github.com/cyanheads/gdelt-mcp-server/issues/78))
