# 0.8.1 — 2026-11-01

## Added

- **Response cache** for DOC and TV requests: an identical request is answered from memory for 15 minutes (24 hours once its explicit window ended more than a day before the fetch), and concurrent identical calls share one fetch. When GDELT rate-limits the refetch, is unavailable (5xx, timeouts), or answers it empty, every DOC and TV tool returns the stored answer instead and marks it with **`staleResponse`** (`fetchedAt`, `ageSeconds`, `reason`: `gdelt_rate_limited`, `gdelt_unavailable`, `gdelt_empty`). A stored answer stands in for up to 24 hours after its fetch, and a `timespan` answer only while it is younger than the timespan; an invalid query, an unparseable body, or a cancelled call never falls back. A call holding such an answer waits on GDELT at most 45 s, and not at all while GDELT is rate-limiting the server. The stored answer holds nothing published after `fetchedAt`. ([#74](https://github.com/cyanheads/gdelt-mcp-server/issues/74))
- **Local GKG mirror** the four DOC tools (`gdelt_search_articles`, `gdelt_get_coverage_timeline`, `gdelt_get_tone_distribution`, `gdelt_get_coverage_breakdown`) answer from when the DOC API refuses a request, or returns nothing and the mirror finds a match, marked by `source`, `attempts`, and `coverage`. Off unless `GDELT_MIRROR_PATH` is set; `GDELT_MIRROR_WINDOW_DAYS` sets the days kept (default 7, 1–90). Build it with `bun run mirror:init`, `mirror:refresh`, and `mirror:verify` from a checkout or the Docker image, which carries the scripts and a `/var/lib/gdelt-mirror` mount point; the npm package does not ship them. A call the mirror can answer (a completed init, a query it compiles of at most 1,000 characters, and a window overlapping the slots it holds) holds DOC to a 45 s budget and gets the mirror's answer by 55 s; any other call waits on DOC as before, and a DOC refusal returns DOC's error with the mirror's reason. ([#75](https://github.com/cyanheads/gdelt-mcp-server/issues/75))
  - Mirror keywords match article titles and entity names, and counts, shares, and the `volume_raw` denominator come from mirrored articles, so figures differ from DOC's; the answer's notice says so.

## Changed

- **DOC empty-result notices** add a sentence to retry the same call later, since GDELT also answers empty under load. Mirror answers do not carry it. ([#77](https://github.com/cyanheads/gdelt-mcp-server/issues/77))
- **Date-field descriptions** on `gdelt_get_coverage_timeline`, `gdelt_get_coverage_breakdown`, and `gdelt_get_tone_distribution`, which said nothing about how far back an explicit window reaches, state which modes accept one older than 3 months (timeline `volume` and `tone`, both breakdowns, tone distribution). The timeline tool's closing "Note: DOC API covers only the last 3 months.", the server instructions' "DOC covers the last three months", and `gdelt-guide` gate 1 are qualified to match. `timespan` still reads "Maximum 3 months.", and validation is unchanged. ([#16](https://github.com/cyanheads/gdelt-mcp-server/issues/16))

## Fixed

- **Relative windows** resolve in UTC, as GDELT reads `timespan`: on a daylight-saving transition day in the server's time zone `1d`/`24h` spanned 25 h or 23 h, and a TV station whose end date is today read as inactive east of UTC. The `timespan` string still goes to GDELT unchanged; the resolved window feeds notices, continuation windows, stale-serve age limits, and the mirror's window. ([#78](https://github.com/cyanheads/gdelt-mcp-server/issues/78))
