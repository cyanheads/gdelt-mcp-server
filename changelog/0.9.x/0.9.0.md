# 0.9.0 — 2026-11-10

## Added

- **Empty TV results name the selected stations whose monitoring range the window misses**, with that range and how to search inside it, in `notice` on `gdelt_search_tv`, `gdelt_get_tv_clips`, `gdelt_get_tv_context`, and `gdelt_get_tv_breakdown`. A station still monitored when the catalog was read is never reported as ended. The ranges come from the station catalog the server already loads to resolve station IDs: until a load has succeeded in the process, an empty result for `stations` with a known window makes one catalog request, paced like any GDELT request and waited on no longer than the call's existing catalog wait; a failed load is not kept. ([#82](https://github.com/cyanheads/gdelt-mcp-server/issues/82))

## Changed

- **Breaking: `stations` on the four TV tools refuses any entry that is not letters and digits** with `invalid_query` before any request ([#81](https://github.com/cyanheads/gdelt-mcp-server/issues/81)). Invisible format characters are removed and entries trimmed first, and blank entries are dropped. 0.8.1 answered `["CNN."]`, `["CNN*"]`, and `["CNN-W"]` as `["CNN"]`, and `["CNN,MSNBC"]` as CNN alone; pass bare station IDs from `gdelt_list_tv_stations` instead.
- **TV `timespan` descriptions** say a relative window counts back from now, past the end of most stations' monitoring, and point to `startDatetime`/`endDatetime` inside a station's range. Each TV tool's `invalid_query` contract and `notice` description now match its handler. ([#82](https://github.com/cyanheads/gdelt-mcp-server/issues/82))
- **GDELT's "TIMESPAN is too far in the past" rejection** gets its own recovery hint: a shorter timespan, or explicit dates inside the archive. ([#82](https://github.com/cyanheads/gdelt-mcp-server/issues/82))
- **`limit` descriptions** on `gdelt_get_coverage_timeline`, `gdelt_get_tone_distribution`, and `gdelt_get_coverage_breakdown` no longer name `GDELT_CLAMP_LIMITS`; they read as the TV tools' do. ([#83](https://github.com/cyanheads/gdelt-mcp-server/issues/83))
- **Mirror refresh skips while another process holds the store's sync lease.** The scheduled HTTP tick logs the skip and the next one catches up; `mirror:init` and `mirror:refresh` exit 1 with `Mirror sync is already in progress`. A refresh stopped by shutdown no longer logs as a failed job.
- **mcp-ts-core ^0.13.22 error handling:** an upstream response body no longer reaches the error `data` a client receives (the server's log still records it); the error trailer gains a `retry after <value>` term when the error carries `retryAfter`; a `fetch` abort that neither the timeout nor the caller caused, and a 2xx body that fails mid-stream, surface as retryable `gdelt_unavailable`.
- **`engines.bun` rises to `>=1.4.4`.** On an older Bun, a server with `GDELT_MIRROR_PATH` set exits at startup with a `ConfigurationError` naming the required and the running Bun version, and `mirror:init`, `mirror:refresh`, and `mirror:verify` exit 1 with the same message; upgrade Bun (the Docker image already runs 1.4.4). Without a mirror, nothing checks the Bun version.

## Fixed

- **Markdown escaping no longer corrupts bare URLs and emails in GFM renderers.** A run of text that needs an escape also gets its `//`, `www.`, and `@` autolink triggers escaped, so no renderer links a half-escaped URL or address; a run that needs none is unchanged. ([#79](https://github.com/cyanheads/gdelt-mcp-server/issues/79))
- **A list-item value whose leading block marker (`-`, `#`, `1.`) sits beside a line break**, after the marker or before it at the start of the value, no longer opens a nested block in `content[]`.
- **A `stations` entry with leading whitespace (`" CNN"`), or a blank entry beside station IDs (`["", "CNN"]`), no longer fails with GDELT's `Invalid Station:`**: entries are trimmed and blank ones dropped before the request, so both answer as CNN. ([#81](https://github.com/cyanheads/gdelt-mcp-server/issues/81))
- **The station-catalog lookup starts no request for a call already cancelled, or once the call has spent its catalog wait.**
