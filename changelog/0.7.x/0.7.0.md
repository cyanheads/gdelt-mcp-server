# 0.7.0 — 2026-10-14

## Added

- **`offset` / `nextOffset` on `gdelt_get_coverage_timeline`, `gdelt_get_tone_distribution`, and `gdelt_get_coverage_breakdown`** — a response carries as many whole timesteps, bins, or series as fit 48,000 bytes per surface; a cut page returns `nextOffset` and a notice naming the returned range, and an `offset` past the last unit fails `offset_out_of_range`. `totalCount`, `dateResolution`, the timeline's per-series `pointCount` and `peak`, and the tone `summary` cover the whole result on every page. ([#54](https://github.com/cyanheads/gdelt-mcp-server/issues/54))
- **`gdelt_get_tone_distribution` `bins` input** — returns only the named bins, each with every article link; an unknown value fails `unknown_bin` listing the available bins. ([#54](https://github.com/cyanheads/gdelt-mcp-server/issues/54))
- **`limitClamp`** on `gdelt_search_articles`, `gdelt_get_tv_clips`, `gdelt_search_tv`, and `gdelt_search_themes` — `{ parameter, requested, applied }`, present only when a request was clamped. ([#56](https://github.com/cyanheads/gdelt-mcp-server/issues/56))
- **`stationName`** on `gdelt_search_tv` series and `gdelt_get_tv_clips` clips — GDELT's label for the station (`FOX News`). ([#58](https://github.com/cyanheads/gdelt-mcp-server/issues/58))

## Changed

- **BREAKING: DOC analytics article links** — `gdelt_get_coverage_timeline` (`volume_with_articles`) and `gdelt_get_tone_distribution` carry at most 3 article references per timestep or bin in `structuredContent` and `content[]`, beside `referenceCount`, the true count. Pass `points` (timeline) or `bins` (tone) for the full list of named units; `points` now returns only the named timesteps. ([#54](https://github.com/cyanheads/gdelt-mcp-server/issues/54))
- **BREAKING: `gdelt_get_coverage_breakdown` `series`** — returns only `selectedSeries`, without the top-10 overview or `otherSeriesLabels`; `topSeries` is optional and absent in that case. Series headers label their ranking key as a sum of values. ([#54](https://github.com/cyanheads/gdelt-mcp-server/issues/54), [#55](https://github.com/cyanheads/gdelt-mcp-server/issues/55))
- **BREAKING: `station` on `gdelt_search_tv` series and `gdelt_get_tv_clips` clips** — holds the station ID (`FOXNEWS`), which `stations` accepts, and is optional: absent when the ID cannot be resolved. `stationName` carries the label that `station` held, and is `""` for a series or clip GDELT returns with no label. The catalog behind the IDs loads once per process; if it cannot load, rows keep `stationName` and the notice says so. Read `stationName` where you read `station`. ([#58](https://github.com/cyanheads/gdelt-mcp-server/issues/58))
- **BREAKING: `limit` and `maxRecords` echoes** — the `limit` and `maxRecords` in a response report the value the call ran with, which differs from the request when `limitClamp` is present. ([#56](https://github.com/cyanheads/gdelt-mcp-server/issues/56))
- **Count-input caps** — a value above the per-call cap and at most 10× it runs at the cap instead of failing: `maxRecords` 250 (reject above 2,500) and 3,000 (above 30,000), `gdelt_search_tv` `limit` 500 (above 5,000), `gdelt_search_themes` `limit` 100 (above 1,000). ([#56](https://github.com/cyanheads/gdelt-mcp-server/issues/56))
- **Caller text in notices, error messages, and recovery hints** — queries and filters are JSON-quoted and Markdown-escaped in `content[]`, so a newline or markup cannot end a notice or render. `structuredContent` echoes stay verbatim. ([#60](https://github.com/cyanheads/gdelt-mcp-server/issues/60))
- **`@cyanheads/mcp-ts-core` ^0.13.13 → ^0.13.15** — a tool-argument rejection (`-32602`) lists at most 10 issues, then ` (+N more)` ([cyanheads/mcp-ts-core#648](https://github.com/cyanheads/mcp-ts-core/issues/648), mcp-ts-core 0.13.14); a numeric string for `limit`, `maxRecords`, or `offset` (`"5"` → `5`) and a lone string for `stations` (`"CNN"` → `["CNN"]`) are repaired before validation.
- **Docs and metadata** — the README carries the MCP SDK `^2.3.1` and Bun `v1.4.3` badges; `framework-skills/` synced (`add-tool`, `api-canvas`, `api-config`, `api-errors`, `api-telemetry`, `api-testing`, `api-utils`, `design-mcp-server`, `field-test`, `git-wrapup`, `polish-docs-meta`, `security-pass`).

## Removed

- **BREAKING: `gdelt_get_coverage_breakdown` `otherAggregated`** and its "Other" section — summing shares of different sources' output is not a share. Read the folded series by passing labels from `otherSeriesLabels` to `series`. ([#55](https://github.com/cyanheads/gdelt-mcp-server/issues/55))

## Fixed

- **`gdelt_unavailable` for every transient upstream failure** — an HTML or empty HTTP 200 body, HTTP 5xx, and a network error now end on the `gdelt_unavailable` contract at the default timeout, keeping `status`, `errorSource`, and `retryAttempts` in `data`; a caller abort and HTTP 501 are unchanged. ([#51](https://github.com/cyanheads/gdelt-mcp-server/issues/51))
- **`gdelt_get_tv_context` sampling** — every non-empty response says in `notice` that terms and scores come from GDELT's relevance-ranked sample of matching clips, documented as the 200 most relevant. ([#57](https://github.com/cyanheads/gdelt-mcp-server/issues/57))
- **`gdelt_search_tv` per-station summary** — the text line reads `Points on this page` and `Page peak`, not a series total. ([#59](https://github.com/cyanheads/gdelt-mcp-server/issues/59))
