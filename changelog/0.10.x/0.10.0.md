# 0.10.0 — 2026-11-14

## Added

- **`gdelt_search_sentences`** — sentence-level search of the last 72 hours of English-language coverage through GDELT's Context 2.0 API, each match with its sentence, surrounding text, and article ([#90](https://github.com/cyanheads/gdelt-mcp-server/issues/90)). GDELT's Context API reads window bounds only to the minute, so an explicit `endDatetime` goes upstream rounded up to the minute and the edge `continuationWindow` moves sits on a whole minute. A page whose matches all fall in one minute is reported as blocked: at the 200 `maxRecords` ceiling it hands back the window past that minute, with a notice naming the skipped minute. `domain:` and `domainis:` are not advertised, and `sourcelang:` draws its own rejection.
- **Each `gdelt_search_tv` series carries `pointCount` and `peak` for the whole series on every page** ([#88](https://github.com/cyanheads/gdelt-mcp-server/issues/88)).
- **Each `gdelt_get_coverage_breakdown` series carries `operator`**, a paste-ready `sourcecountry:<FIPS>` or `sourcelang:<name>`; it is omitted for a name with no code or several ([#91](https://github.com/cyanheads/gdelt-mcp-server/issues/91)).

## Changed

- **The four DOC tools refuse a whitespace-only `query` and a `timespan` that is not a number with an optional unit** (`banana`, `d`, `garbage`, `min15`, `1d!`, `7d foo`, text after a line break) before any request ([#92](https://github.com/cyanheads/gdelt-mcp-server/issues/92)). 0.9.0 sent them upstream verbatim; a bare number (`60`) and `15mins`/`1.5d`/`7 days` are still sent.
- **GDELT's "Invalid/Unsupported Language" rejection on the DOC tools draws a `sourcelang:` hint**: spell the language name out in English, such as `sourcelang:spanish`.
- **`seendate` is described as when GDELT saw the article**, not its publication time.
- **TV continuation guidance says the TV API answers in whole UTC periods**, and TV point dates are described as GDELT labels them: 12:00:00Z of the period's first day for day-and-longer periods.
- **`gdelt_get_tv_context` breaks score ties by label.**
- **`gdelt_list_tv_stations` escapes the brackets around its station list in `content[]`.**
- **Context is named beside DOC and TV** in the shared pacer, response cache, and `GDELT_BASE_URL` docs.

## Fixed

- **`structuredContent.notice` carries caller and upstream text raw**: values are JSON-quoted with no Markdown escapes, and `content[]` renders the same notice escaped ([#85](https://github.com/cyanheads/gdelt-mcp-server/issues/85)).
- **`gdelt_get_coverage_breakdown` ranks and pages every series**: `limit` (default 10, cap 75) and `offset` page the whole ranked list with `nextOffset`, `otherSeriesLabels` names the ranked series not on the page, and a `series` label several series share selects all of them ([#86](https://github.com/cyanheads/gdelt-mcp-server/issues/86)).
- **TV timeline, ranking, and word-cloud values cover whole UTC periods**, and when an explicit `startDatetime`/`endDatetime` edge falls inside a period the notice names the UTC window the values cover ([#87](https://github.com/cyanheads/gdelt-mcp-server/issues/87)).
- **Rendered sums are the exact sum of the shown values, and mirror-computed shares, tone means, and smoothed values carry four decimals**, rounded after smoothing ([#89](https://github.com/cyanheads/gdelt-mcp-server/issues/89)).
- **`gdelt_search_articles` discloses its 3-month reach in `windowClamp`** when a longer `timespan` runs on 3 months; the request still carries the value sent ([#92](https://github.com/cyanheads/gdelt-mcp-server/issues/92)).
- **The DOC "timespan is too short" hint covers explicit windows**, not only a relative `timespan` ([#92](https://github.com/cyanheads/gdelt-mcp-server/issues/92)).
- **`gdelt_get_tv_clips` sends a window of 2 hours or more with the caller's start**, so a 7-day or just-under-3-year window is no longer answered at a coarser period.
