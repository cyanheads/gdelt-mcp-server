# 0.10.1 — 2026-11-18

## Added

- **`gdelt_get_coverage_breakdown` series carry `sum`, `pointCount`, and `peak`** for the whole series on every page, and `includePoints: false` (default `true`) leaves `data` out of every returned series; ranking and paging do not change ([#96](https://github.com/cyanheads/gdelt-mcp-server/issues/96)).

## Changed

- **A mirror answer to a query that requires a keyword or phrase names the `theme:` route**: GKG themes are tagged on translated articles too, so a `theme:` element in place of the keyword reaches non-English coverage the keyword misses. The sentence is on all four DOC tools, with matches or none ([#95](https://github.com/cyanheads/gdelt-mcp-server/issues/95)).
- **A mirror answer to a query with no keyword or phrase no longer says keywords matched titles and entity names.**
- **`dateResolution` on the timeline and breakdown is the one GDELT reports**, inferred from the spacing of the returned timesteps only when it reports none.
- **`GDELT_MIRROR_PATH` in `server.json` says the mirror also answers a DOC window under 30 minutes**, which DOC is never asked.
- **`gdelt-guide` skill 1.4** covers the 30-minute window floor, the on-the-hour TV end, and the mirror's `theme:` route.

## Fixed

- **`gdelt_get_coverage_timeline` and `gdelt_get_coverage_breakdown` report `missingTimesteps`**, the timesteps GDELT left out between the first and last it returned, and the notice names each missing run as a gap in GDELT's data, not zero coverage. It is the same on every page and in every mode, and absent for a mirror answer ([#98](https://github.com/cyanheads/gdelt-mcp-server/issues/98)).
- **`gdelt_search_tv`, `gdelt_get_tv_breakdown`, and `gdelt_get_tv_context` send an `endDatetime` on the clock hour one second early**, so `20240924000000`–`20241004000000` ends with Oct 3 instead of counting all of Oct 4 ([#97](https://github.com/cyanheads/gdelt-mcp-server/issues/97)). `gdelt_search_tv` keeps its point resolution at exactly 3×365 days and 7 days and a second; a window the trim would leave under 30 minutes goes as given.
- **A rate limit closes the cooldown only for the API that returned it** (DOC, TV with its station catalog, or Context), which doubles on that API's own rate limits and resets on its own success; the request slot and gap stay shared ([#93](https://github.com/cyanheads/gdelt-mcp-server/issues/93)).
- **The four DOC tools never send DOC an explicit window under 30 minutes** ([#92](https://github.com/cyanheads/gdelt-mcp-server/issues/92)). The mirror answers it where one runs, with `attempts` opening on `window_too_short`; otherwise the call fails `invalid_date_range` before any request. `continuationWindows` is not offered for a window under 60 minutes.
